#+title: burnscars: Rust port of the controlledburn core — design

* Summary

~burnscars~ is a minimal, idiomatic Rust port of the controlledburn core
(~~/repos/controlledburn/cpp~). It rasterizes polygons, lines and points onto a
regular grid. It gives sparse output, in O(perimeter) time and memory. It has two
polygon paths:

- *Coverage*: the exact fraction of each boundary cell that the polygon covers.
- *Approx*: the cell-centre rule (the GDAL and fasterize rule).

The crate has no internal parallelism. Its API lets an external orchestrator (for
example brix) run work in parallel, by geometry or by grid chunk. The design leaves
room for a later per-cell DE-9IM estimate (see [[*Future: DE-9IM][Future: DE-9IM]]).

* Scope

In v1:
- Lattice and grid types, with exact sub-windows.
- Input through ~geo-traits~ (0.3): Point, LineString, Polygon, the Multi types,
  Rect, Triangle, Line.
- Coverage path and approx path for polygons. Length in cell for lines. Cell
  membership for points.
- The four-table output in SoA form, with a per-geometry index and a row-major view.
- Typed errors.
- Tests, the oracle suite, benchmarks, tooling and CI.

Input validity: the crate supports valid OGC input only. For invalid input (rings
that intersect themselves, components that overlap), the output is not specified, but
it is deterministic. Fill rule: nonzero winding. The approx oracle, GDAL
~GDALdllImageFilledPolygon~ (~alg/llrasterize.cpp~), uses even-odd: it sorts the
crossings of each scanline and fills between pairs. For valid input the two rules give
the same result. GDAL also samples at the cell centre (~y + 0.5~) and uses a half-open
edge test (~dy < dy2 && dy >= dy1~ in image rows), which is the same as the approx
rule ~ya < y_mid <= yb~ in world coordinates.

Not in v1 (the README TODO lists these items, see [[*README TODO list][README TODO list]]):
- Materialize and pixel functions (a brix adapter will do this).
- Crop, extract, bindings.
- Antimeridian handling.
- DE-9IM.
- The optimizations R1–R4.
- A performance regression gate.
- rayon or any other internal parallelism.

* Terms

- *Lattice*: an infinite regular grid. Column edge ~k~ is at ~x0 + k*dx~. Row edge ~k~
  is at ~y0 - k*dy~. Row 0 is at the top.
- *Grid*: a lattice, a full extent (a finite range of rows and columns), and a window
  inside the full extent. Indices in the output are global lattice indices.
- *Run*: the interior cells ~[col_start, col_end)~ of one row that one geometry fully
  covers.
- *Edge*: one boundary cell of a polygon with its coverage fraction in (0, 1).
- *Traversal*: one pass of a ring or line through one cell. It has an entry point, zero
  or more vertices, and an exit point. Source: exactextract ~Traversal~
  (~src/traversal.h~).
- *Walker grid*: the processing region of one geometry plus one padding cell on each
  side, with local ~usize~ indices. This is exactextract ~Grid<infinite_extent>~
  (~src/grid.h~). Local row and column 0 are padding.
- *Winding*: the signed count of ring crossings of the cell-centre line ~y_mid~ of a
  row, taken from the left. A cell is inside if the winding is not zero.
- *Coverage matrix*: the sparse matrix ~A[cell, geometry]~. The value is the coverage
  fraction, and it is 1 for interior cells. See [[*Output tables][Output tables]].
- *Expanded form*: each table record written as per-cell tuples ~(id, row, col, value)~.
  A run gives one tuple with ~value = 1~ for each of its cells.

* Public API

** Grid

#+begin_src rust
/// Infinite regular lattice. Column edge k is `x0 + k*dx`; row edge k is `y0 - k*dy`.
/// Row 0 is at the top. Cell (r, c) is `[x_edge(c), x_edge(c+1)] x [y_edge(r+1), y_edge(r)]`.
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct Lattice { x0: f64, y0: f64, dx: f64, dy: f64 }

/// A window of a full extent on a lattice. All ranges are global lattice indices.
/// `window()` keeps the full extent, so the edge rules of the full grid hold in every chunk.
#[derive(Clone, Debug, PartialEq)]
pub struct Grid {
    lattice: Lattice,
    full_rows: Range<u32>, full_cols: Range<u32>,   // the full grid
    rows: Range<u32>, cols: Range<u32>,             // the window; inside the full grid
}

impl Lattice {
    /// Errors: non-finite value, `dx <= 0`, `dy <= 0`.
    pub fn new(x0: f64, y0: f64, dx: f64, dy: f64) -> Result<Self, GridError>;
    pub fn x_edge(&self, col: i64) -> f64;   // x0 + col as f64 * dx
    pub fn y_edge(&self, row: i64) -> f64;   // y0 - row as f64 * dy
    /// The column c with x_edge(c) <= x < x_edge(c + 1). See "Index authority".
    pub fn col_of(&self, x: f64) -> i64;
    /// The row r with y_edge(r + 1) < y <= y_edge(r). See "Index authority".
    pub fn row_of(&self, y: f64) -> i64;
}

impl Grid {
    /// Full grid = window = `rows` x `cols`.
    pub fn new(lattice: Lattice, rows: Range<u32>, cols: Range<u32>) -> Result<Self, GridError>;
    /// Same meaning as controlledburn `GridSpec`: x0 = xmin, y0 = ymax,
    /// dx = (xmax - xmin) / ncol, dy = (ymax - ymin) / nrow, rows 0..nrow, cols 0..ncol.
    pub fn from_extent(xmin: f64, ymin: f64, xmax: f64, ymax: f64,
                       ncol: u32, nrow: u32) -> Result<Self, GridError>;
    /// A sub-window with the same lattice and the same full grid (for example a brix chunk).
    /// Errors if `rows` or `cols` is empty or not inside the full grid.
    pub fn window(&self, rows: Range<u32>, cols: Range<u32>) -> Result<Grid, GridError>;
    pub fn lattice(&self) -> &Lattice;
    pub fn rows(&self) -> Range<u32>;
    pub fn cols(&self) -> Range<u32>;
    pub fn full_rows(&self) -> Range<u32>;
    pub fn full_cols(&self) -> Range<u32>;
}
#+end_src

Rules:
- Every cell edge comes from ~x_edge~ or ~y_edge~, with an integer index. Nothing
  computes an edge from a window corner. Thus a tiled burn and a full burn see identical
  cell boxes.
- ~from_extent~ does not store ~xmax~ or ~ymin~. The right edge of the full grid is
  ~x_edge(ncol)~, which can differ from ~xmax~ by a few ulp.

*** Index authority

The cell edges are the authority. ~col_of(x)~ computes ~c = floor((x - x0)/dx)~ and
then corrects ~c~ by ±1 until ~x_edge(c) <= x < x_edge(c + 1)~. ~row_of(y)~ does the
same with ~y_edge~. Thus the index of a coordinate always agrees with the cell box that
contains it. Points, the walker start cell, the processing region, and the approx sweep
all use ~col_of~ and ~row_of~.

*** Closed edges of the full grid

This follows exactextract ~Grid::get_column~ and ~Grid::get_row~ (~src/grid.h~): a
coordinate exactly on the right edge of the grid belongs to the last column, and a
coordinate exactly on the bottom edge belongs to the last row. In burnscars this rule
applies only at the edges of the *full* grid (~full_cols.end~, ~full_rows.end~), never
at a window edge. Thus the rule gives the same cell in a chunk and in the full burn.

** Output tables

The output is the controlledburn four-table contract, in struct-of-arrays (SoA) form.
All indices are global, 0-based lattice indices. ~col_end~ is exclusive. ~id~ is the id
that the caller gives. Ids do not have to be unique.

/// The table rows of one input item (the CSC index).
#[derive(Clone, Debug, PartialEq)]

    pub lines: Range<usize>, pub points: Range<usize>,

#[derive(Clone, Debug, Default, PartialEq)]

impl BurnResult {
    pub fn clear(&mut self);          // keeps capacity
    pub fn len(&self) -> usize;       // total table rows
    pub fn is_empty(&self) -> bool;

    pub fn to_row_major(&self, rows: Range<u32>) -> Result<RowMajor, RowMajorError>;

/// CSR view. For row r: `runs[run_ptr[r - r0]..run_ptr[r - r0 + 1]]` are indices into
/// `BurnResult::runs`; the same for edges, lines and points. Within a row, the
/// entries keep burn order; they are not sorted by column.
#[derive(Clone, Debug, PartialEq)]
pub struct RowMajor {
    pub rows: Range<u32>,
    pub run_ptr: Vec<usize>, pub runs: Vec<usize>,
    pub edge_ptr: Vec<usize>, pub edges: Vec<usize>,
    pub line_ptr: Vec<usize>, pub lines: Vec<usize>,
    pub point_ptr: Vec<usize>, pub points: Vec<usize>,
}
#+end_src

- ~to_row_major~ is a stable counting sort by row: O(n + rows). It stores permutation
  indices and copies no table data.
- ~geom_ptr~ holds one ~GeomSpan~ for each input item, including empty geometries
  (with empty ranges), in input order.
- ~fraction~ and ~length~ are ~f32~, the same as in controlledburn.

*Required crate and ~BurnResult~ documentation: the relation to sparse matrices.* The
crate docs (~lib.rs~) and the ~BurnResult~ docs must say the following, in Simple
Technical English:
- The polygon output is the sparse coverage matrix ~A[cell, geometry]~. The value is
  the coverage fraction, and it is 1 for interior cells. Zonal statistics are
  ~(Aᵀv) / (Aᵀ1)~ for a raster ~v~. This is what exactextract computes.
- ~runs~ is a run-length layer: each entry is one interval of columns, all with the
  value 1 ("RLE-CSR"). Plain CSR stores one entry per cell, which is O(area). The runs
  keep the storage at O(perimeter).
- ~edges~ is COO: explicit ~(row, col, value)~ triples.
- The burn order is geometry-major, so ~geom_ptr~ is a CSC index, with the geometry as
  the column.
- ~to_row_major()~ builds the CSR index (~row_ptr~).
- Two geometries can cover the same cell, so the full object is a sparse
  ~(row, col, id)~ tensor. One geometry has at most one record per cell (see
  [[*Multipolygons][Multipolygons]]).

- ~part~ is the index of the component in a Multi geometry, and 0 for a single
  geometry. ~ring~ is the index of the ring in its polygon (0 = exterior). For points,
  ~vertex~ is 0 and ~ring~ is 0.
- ~Internal~ replaces a panic: for example, a walker index that leaves the walker grid.
  The library code never panics on input data.
- ~Burner::burn_into~ stops at the first error. An orchestrator that wants "skip and
  report" calls it once for each geometry. That costs no extra allocation, because the
  scratch buffers stay in the ~Burner~.

** Output order and determinism

The output order is:
1. ids in the order the caller gives them;
2. for a polygon geometry: rows ascending, then columns ascending, in each table;
3. for a line geometry: rows ascending, then columns ascending (the merged cells of all
   parts);
4. for a point geometry: input order.

*Partition equality* is defined on the expanded form. A tiled burn and a feature-split
burn must each give the same multiset of ~(id, row, col, value)~ tuples as the full
burn, for each table. A run that crosses a seam splits into two runs, so the records
themselves can differ.

** Parallelism contract

The core is sequential. An orchestrator runs it in parallel like this:
- *Feature-parallel*: each worker has its own ~Burner~ and ~BurnResult~, and burns a
  range of ~(id, geometry)~ pairs onto the full grid. The merge is a concatenation.
- *Raster-parallel* (brix chunks): each worker burns the geometries whose ~bbox~ meets
  its chunk onto ~grid.window(rows, cols)~. Each chunk output is complete for its
  window, so no merge is necessary.
- ~Grid~ is ~Clone + Send + Sync~. ~Burner~ and ~BurnResult~ are ~Send~.
- Known v1 limit: each chunk scans every vertex of each geometry that meets it, so a
  large polygon over many chunks costs O(vertices × chunks). R3 and R4 remove this.

* Algorithms

The arithmetic is a faithful port. Only the storage changes (see [[*Storage][Storage]]). Each
ported item has a docstring that names its upstream file and function (see
[[*Documentation rules][Documentation rules]]).

** Input normalization (~input.rs~)

- The input is read through ~geo-traits~ ~GeometryTrait~. Only ~x()~ and ~y()~ of
  each coordinate are used, and Z and M are ignored.
- *Kinds*: Rect becomes a 4-corner polygon. Triangle becomes a polygon. Line becomes a
  2-point line string. GeometryCollection gives ~BurnError::Unsupported~.
- *Rings* are copied into the ~Scratch~ coordinate buffer. If the first coordinate is
  not equal to the last one, the copy appends the first coordinate (auto-close).
- *Ring sizes*: a ring with 0 coordinates is skipped. After the auto-close, a ring
  with fewer than 4 coordinates gives ~ShortRing~. (controlledburn skips it silently.)
- *Line sizes*: a line with 0 coordinates is skipped. A line with 1 coordinate gives
  ~ShortLine~. A line whose coordinates are all equal gives no records.
- *Non-finite* coordinates give ~NonFinite~. Exception: a point whose ~coord()~ is
  ~None~ (POINT EMPTY) is skipped.
- *Empty geometries* are skipped. They still get a ~GeomSpan~.
- *Orientation*: signed area by the shoelace formula, with counter-clockwise positive.
  This is controlledburn ~signed_area~ (~cpp/src/scanline.cpp~). A ring that is not
  CCW is reversed in the copy. Note: exactextract ~area~ (~src/measures.cpp~) uses the
  opposite sign. The port keeps both functions under different names and documents the
  sign of each.

** Processing region (polygons and lines)

Source: exactextract ~processing_region~ and ~get_geometry_grid~
(~src/raster_cell_intersection.cpp~).
- The region is the union of the component envelopes, intersected with the grid
  window.
- If the region is empty, the geometry gives no output.
- On the lattice, the column range is ~col_of(xmin) - 1 ..= col_of(xmax) + 1~. The row
  range is ~row_of(ymax) - 1 ..= row_of(ymin) + 1~: ~ymax~ gives the low row index,
  because row 0 is at the top. Both ranges are then clamped to the window.
- The one-cell margin replaces the floating-point fixes in exactextract
  ~Grid::shrink_to_fit~ (~src/grid.h~). It makes sure that the region contains the
  cell of every vertex near the envelope, even if that vertex is a few ulp from a wall.
  It never goes past the window.
- The walker grid is this region plus one padding cell on each side, with local
  ~usize~ indices. This follows exactextract ~Grid<infinite_extent>~: local index 0 is
  the left (or top) padding, local ~1..=n~ are the real cells, and local ~n + 1~ is the
  right (or bottom) padding. A padding cell box goes from the region edge to ~f64::MAX~
  (or ~-f64::MAX~). The code converts a local index to a global ~u32~ only at emit
  time: ~global = region_start + local - 1~.

*** Walker

Port ~walk_polyline~ arithmetic without change, except for rule 1. These rules are
required, and each one has a regression test:
1. *Lattice snap* (from controlledburn ~snap_to_lattice~; exactextract does not snap):
   before the walk, each vertex within ~1e-9 * dx~ of a lattice column edge moves onto
   that edge, and the same for ~dy~ and row edges. The edge index is
   ~k = round((x - x0)/dx)~, and the edge is ~x_edge(k)~. Change from controlledburn:
   there is *no range test*. controlledburn snaps only to edges inside the padded
   subgrid, which depends on the window and breaks partition equality.
2. *Start cell* from the first coordinate, with exactextract ~Grid::get_row~ /
   ~get_column~ semantics on the walker grid: a coordinate left of (or above) the
   region goes to padding 0, and a coordinate right of (or below) it goes to padding
   ~n + 1~. Inside, the cell comes from ~col_of~ / ~row_of~. The closed-edge rule
   applies only at the edges of the full grid (see [[*Closed edges of the full grid][Closed edges of the full grid]]).
3. *Point location*: ~strictly_contains~ means inside, ~contains~ means on the
   boundary, and anything else is outside.
4. *Exit crossing*: ~Box::crossing(from, next)~, where ~from~ is the previous original
   vertex if there is one, else the last traversal coordinate.
5. *Rounding guard*: if the crossing is not finite, or is further from ~from~ than
   ~next~ by more than a factor of ~1 + 1e-9~ (in squared distance), the exit point is
   ~next~ clamped onto the box. The exit side is the side that ~next~ overshoots,
   tested in the order left, right, bottom, top.
6. *Forced exit*: if a traversal ends on the box boundary with no exit side, its exit
   side is ~box.side(last)~.
7. *Reprocess branch* (closed rings only): if the first traversal has an exit but no
   entry, its coordinates are appended to the end of the ring buffer, so that the walk
   enters the start cell again with a proper entry side. If the buffer grows past
   ~4 * n_input + 64~, the walk gives ~WalkDiverged~.
8. *Move*: the exit side moves the walk one cell (TOP: row - 1; BOTTOM: row + 1;
   LEFT: col - 1; RIGHT: col + 1). If the move leaves the walker grid (a local index
   below 0 or above ~n + 1~), the walk gives ~Internal~.

The walker records traversals in the arena (see [[*Storage][Storage]]), not in a map.

*** Cell fraction

For each real cell of the walker grid, take the valid traversals. A traversal is valid
if it has an entry side and an exit side and more than one unique coordinate, or if it
has no entry side and is a closed ring.
- One valid traversal that is a closed ring: ~|area| / cell_area~
  (~closed_ring_covered_fraction~).
- One valid traversal that is not a closed ring: ~analytical_covered_fraction~. This is
  the traversal path, plus the cell corners on the clockwise arc from the exit back to
  the entry, closed. Corners are tested with the ~1e-12~ margins of the original. If
  the entry and exit perimeter distances are within ~1e-12~ of each other, the result
  is the area of the closed path.
- More than one valid traversal: exactextract ~left_hand_area(box, traversals) /
  cell_area~.

The fraction gets a factor of +1 for an exterior ring and -1 for a hole.

*** Winding deltas

For each valid traversal that has an entry and an exit (closed rings give no winding),
with ~y_mid~ the cell-centre y of the row:
- The traversal crosses if
  ~(entry_y >= y_mid && exit_y < y_mid) || (entry_y < y_mid && exit_y >= y_mid)~. The
  test is half-open: a point on ~y_mid~ counts as above it. This is controlledburn fix
  ~0efe32f~.
- The delta is -1 if ~entry_y >= y_mid~ (downward), else +1. It is multiplied by +1 for
  an exterior ring and -1 for a hole.
- The deltas are recorded even when the fraction is zero. A traversal along a cell wall
  has zero area but still crosses ~y_mid~.
- The padding columns (local 0 and ~n + 1~) carry winding deltas for their row. The
  padding rows are ignored.

*** Multipolygons

Follow upstream (exactextract ~RasterCellIntersection::process~). All rings of all
components of one geometry go into one accumulator, with one processing region and one
sweep. So one geometry gives at most one record per cell.
- controlledburn sweeps each component separately. Its comment says that this prevents
  winding "bleed" between components. The design does not keep that, for two reasons:
  - In coverage mode an edge value comes from its fraction, not from the winding.
  - The winding numbers of disjoint components add correctly.
- The multipolygon tests and the oracle check this decision.
- *Fallback, only if the oracle shows a bleed*: one sweep per component, then a merge of
  records with the same ~(row, col, id)~. The merge adds the fractions and changes a sum
  ~>= 1 - 1e-6~ to a one-cell run. Report this to the user before you use the fallback.

*** Sweep

For each real row of the walker grid, with the accumulator sorted and merged by local
column (fractions added, deltas added):
- ~winding = 0~, ~prev_col: Option<usize> = None~.
- For each merged cell at local column ~c~ (padding columns included):
  - If ~winding != 0~ and ~prev_col == Some(p)~ and ~c > p + 1~: emit the run
    ~[p + 1, c)~. This is controlledburn's ~prev_col > -2~ rule: a padding cell counts
    as seen.
  - If ~c~ is a real column: with ~w~ = the fraction and ~tol = 1e-6~, emit an edge if
    ~tol < w < 1 - tol~, and emit the one-cell run ~[c, c + 1)~ if ~w >= 1 - tol~.
  - ~winding += delta(c)~; ~prev_col = Some(c)~.
- A run is clamped to the real columns ~1..=n~ before the conversion to global indices.
  Every emit is guarded by ~start < end~.

The dead approx branch of ~walk_ring~ (~winding_delta_left~) is not ported:
controlledburn ~process_geometry~ always sends approx polygons to
~process_polygon_approx~.

** Approx path

Source: controlledburn ~process_polygon_approx~ (~cpp/src/scanline.cpp~). The
arithmetic is a faithful port, on the lattice. Change from controlledburn: all rings
of all components of the geometry go into one intercept set and one sweep, and the row
range comes from the union envelope. controlledburn runs one sweep per component with
the exterior envelope only. The union gives one record per cell, which matches the
coverage path.
- The row range is the envelope rows clamped to the window:
  ~row_lo = max(r0, row_of(ymax))~ and ~row_hi = min(r1 - 1, row_of(ymin))~.
- For each ring, the winding factor is +1 if the ring is CCW, else -1. It is negated for
  a hole.
- For each edge ~(x0e, y0e) -> (x1e, y1e)~ with ~y0e != y1e~: take ~ya < yb~. The rows
  are those with ~ya < y_mid(r) <= yb~, where ~y_mid(r) = y0 - (r + 0.5)*dy~:
  ~e_lo = max(row_lo, ceil((y0 - yb)/dy - 0.5 - 1e-10))~ and
  ~e_hi = min(row_hi, ceil((y0 - ya)/dy - 0.5 - 1e-10) - 1)~.
- The intercept is ~x = x0e + (y_mid - y0e)/(y1e - y0e) * (x1e - x0e)~.
- The delta is ~(y1e < y0e ? -1 : +1) * factor~. It comes from the edge endpoints, not
  from ~y0e~ against ~y_mid~. This is controlledburn fix ~65af8d7~.
- *Sweep* for each row, with the intercepts sorted by ~x~ (~f64::total_cmp~):
  ~col = col_of(x)~ clamped to the window columns, ~x_mid = x_edge(col) + 0.5*dx~, and
  left of centre means ~x <= x_mid~ (left-inclusive).
  - Left of centre: going from not-zero to zero closes the run before ~col~. Going from
    zero to not-zero starts the run at ~col~.
  - Right of centre: going from not-zero to zero closes the run after ~col~ (clamped to
    the window end). Going from zero to not-zero starts the run at ~col + 1~.
  - If the winding is not zero at the row end, the run goes to the window end.
  - Every emit is guarded by ~start < end~.
- The approx path gives no edges.

** Lines

Source: controlledburn ~process_line~ (~cpp/src/scanline.cpp~), and exactextract
~RasterCellIntersection::process_line~ and ~add_ring_results~
(~src/raster_cell_intersection.cpp~) for the accumulation of parts. Each part of the
line is walked with ~closed = false~ (no reprocess branch; a traversal with no entry
side is valid). For each real cell, the length is the sum of the segment lengths of all
traversals of all parts. A cell with a length > 0 gives one ~Lines~ record. This
follows exactextract, which adds all parts into one matrix. controlledburn gives one
record per part.
Change from controlledburn: the walker uses the processing region of the window, not
the full grid. A horizontal or vertical line has a degenerate envelope; the one-cell
margin makes the region non-empty.

** Points

- The cell is ~(row_of(y), col_of(x))~, with the closed-edge rule at the edges of the
  full grid (see [[*Closed edges of the full grid][Closed edges of the full grid]]). This gives the same cells as exactextract
  and controlledburn for a full-grid burn.
- The point is emitted if its cell is inside the window.

* Storage

The arithmetic does not change. Only the storage changes.

| #  | controlledburn (C++)                                                      | burnscars                                                                                                                                 | Gain                                  |
|----+---------------------------------------------------------------------------+-------------------------------------------------------------------------------------------------------------------------------------------+---------------------------------------|
| O1 | ~std::map<(row,col), CellRecord>~, one ~vector<Coordinate>~ per traversal | arena: ~coords: Vec<Coord>~ and ~travs: Vec<Trav { row, col, seq, start, len, entry, exit }>~ (local ~usize~), then one ~sort_unstable~ by ~(row, col, seq)~ | no tree, no allocation per cell visit |
| O2 | ~vector<vector<BoundaryCellRecord>>~ with a linear ~find_or_create~       | ~acc: Vec<CellAcc { row: usize, col: usize, cov: f32, wind: i32 }>~ (local indices), one sort by ~(row, col)~, then one merge pass        | no O(k²) scan in a row                |
| O3 | ~analytical_covered_fraction~ builds a polygon ~vector~                   | shoelace sum over the traversal and the corners, with no buffer                                                                           | no allocation per edge cell           |
| O4 | approx: ~vector<vector<Intercept>>~ per polygon                           | ~icpt: Vec<(row: u32, x: f64, delta: i32)>~, sorted by ~(row, x)~                                                                        | one reused buffer                     |
| O5 | lines: ~CellMap~, then a sum                                              | sum over the arena groups                                                                                                                 | same as O1                            |
| O6 | new buffers for each polygon                                              | all buffers live in ~Scratch~ and are cleared between geometries                                                                          | no allocation in steady state         |

- ~seq~ is the visit order. ~left_hand_area~ does not depend on the order of the
  chains, but ~seq~ keeps the result deterministic.
- O3 must be bit-equal to a Rust reference version of ~analytical_covered_fraction~
  (test only) that builds the polygon as in C++, for the same box and traversal. A
  proptest checks this. The C++ code is not run.
- ~Scratch~ is private. It holds: the ring coordinate buffer, ~coords~, ~travs~,
  ~acc~, ~icpt~, and the left-hand-area chain buffer.

- ~oracle/corpus.wkt~: one case per line: a name, the WKT, and a grid

* Future: DE-9IM

This part is not in v1. The v1 types must not block it.

For a polygon P and a cell box C, the DE-9IM matrix can be decoded from a compressed
form: the fraction ~f~, a one-byte contact mask per edge cell, and one bit per geometry.

| Entry  | Source                                                                                      |
|--------+---------------------------------------------------------------------------------------------|
| II     | ~2~ if ~f > 0~, else ~F~                                                                    |
| EI     | ~2~ if ~f < 1~, else ~F~                                                                    |
| EE     | always ~2~                                                                                  |
| IE, BE | per geometry: ~2~ / ~1~ unless P is inside one cell (one bit per geometry)                 |
| BI     | mask bit: a traversal goes through the cell interior                                        |
| BB     | mask bits: ~1~ if a segment lies on a cell wall, ~0~ if contact is at points only, ~F~ if no contact |
| IB, EB | mask bits: part of ∂C is in int P / in ext P (not derivable from ~f~)                        |

- Run cells all have the same matrix (~212F01FF2~, P contains C), so they need no
  storage.
- The later work adds parallel columns ~edge_contact: Vec<u8>~ and a ~touches~ table
  (cells with ~f = 0~ and contact on a wall or corner). The existing tables do not
  change.
- Only the coverage path can give DE-9IM. The approx path has no boundary data.
- Oracle: shapely ~relate(geometry, cell_box)~, used as a black box.
- Upstream rule: no GEOS code and no JTS code. Derive the decode table from the
  DE-9IM definitions.

* Risks

- *Partition bit-exactness*: the entry point into a window cell can come from a padding
  cell in one tiling and from a real cell in another. The crossing uses the same
  original vertices and the same lattice wall, so the result should be identical, but
  this is not proven. ~partition.rs~ finds out.
- *Multipolygon decision*: if the oracle shows winding bleed with one sweep per
  geometry, use the fallback in [[*Multipolygons][Multipolygons]] and report it.
- *Oracle differences*: exactextract has its own lattice edge cases. A difference can
  be an oracle bug. Each one needs a reason in ~known_diffs.toml~.
- *Lattice edges against the C++ subgrid edges*: fractions can differ by a few ulp.
  The parity tolerance (~1e-6~) covers this.
- *Tile cost*: O(vertices × chunks) for large polygons in v1 (see
  [[*Parallelism contract][Parallelism contract]]).
